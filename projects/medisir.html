MediSir POS

TECHNICAL CASE STUDY

Advanced pharmacy management SaaS — the most technically complete system I’ve built.

The Problem

Small and medium pharmacies in Indonesia still rely on manual record-keeping or outdated desktop software. They need a modern, cloud-based POS system that handles inventory, prescriptions, multi-cashier operations, and real-time sync — without expensive enterprise pricing.

What I Built

A production-grade SaaS with deep technical architecture that goes far beyond typical CRUD apps.

  • ✓ Full POS with barcode scanning, multi-payment methods, discounts, and thermal receipt printing + WhatsApp delivery
  • ✓ Multi-tenant architecture with PostgreSQL Row Level Security (RLS) — each pharmacy has completely isolated data
  • ✓ Kasir (cashier) invitation system with 8-character join codes
  • ✓ Realtime inventory sync across all cashiers using Supabase Realtime
  • ✓ Digital prescription module with validity control and direct redemption to POS
  • ✓ Stock movement audit logs, CSV import/export, financial reports with Recharts visualization

The Result & Decision to Pause

The advanced MVP was completed with production-grade architecture — fully functional and ready for deployment.

However, development was paused before commercial launch due to regulatory requirements in the Indonesian healthcare industry: data protection laws for medical records, digital prescription regulations, and pharmacy licensing requirements (SIA/SIPA).

This was not a technical failure — it was a strategic business decision. The codebase remains a strong foundation for pivoting into general retail and inventory management systems (building materials shops, small retail stores, workshops).

Stack

React + TypeScript Vite Supabase (Auth + DB + Realtime + Storage) PostgreSQL + RLS Zustand Recharts Tailwind CSS html5-qrcode
